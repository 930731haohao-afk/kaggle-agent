# 報告結構規格(7 節)

對齊計畫書定義:計畫書分兩部分——(甲)競賽目的(what/why)、(乙)實驗方法五大元件
(資料規格/模型規格/訓練規格/推論程序/評估指標)。本報告的節次結構在(甲)(乙)之外,
額外加入三節報告自身的附加價值(工具/專業術語/階段盤點、逐階段對照、敘述性總結)與既有的
軌跡/重現資訊,合計 7 節:

1. 競賽目的(what/why)= 計畫書(甲)
2. 本場工具、專業術語與採用策略 = 報告額外附加;只放「本場特有」的工具與專業術語,以及本場
   各階段的採用情形(見 2.1–2.3)
3. 實驗方法(3.1–3.5)= 計畫書(乙)五大元件(spec 內部對照用;報告正文標題僅寫
   「實驗方法」,不附此括號說明)
4. 實驗軌跡 = 報告額外附加
5. 效能對照(逐階段)= 報告額外附加,對照計畫書目標三(效能不退步)
6. 總結(敘述性)= 報告額外附加
7. 重現指令 = 報告額外附加

每節列出:必填內容 + facts.json 對應來源。「無紀錄」處理見 SKILL.md Hard Rule 4。

**共同內容放《前言》(全案鐵則)**:全案共同的研究設計、實驗流程、工具鏈、專業術語表與
「階段/子階段」完整定義,一律放在《前言》(`docs/PREFACE.md`,對外交付
`docs/PREFACE.pdf`),各場報告**只放本場特有**的部分,不得把共同內容複製進報告。
《前言》第 5 節(全案專業術語表)與第 6 節(階段與子階段字典,含「簡稱」欄與舊代號對照)
是這兩類內容的唯一出處。

**統一階段語言(全案鐵則)**:全文只使用「階段 1–5 + 純數字子階段(1.1/1.2/2.1–2.4/
3.1–3.5/4.1–4.5/5.1–5.2)」表示方法論進展。禁止出現 tier1–4、Phase A/B/C…、round N、
Batch N 等舊代號;舊代號對照已收在《前言》第 6 節,報告內**不放**對照行。細節見文末
R-W8。

**白話優先(全案鐵則)**:淺顯或次要概念一律用白話敘述,不自創專案內部專業術語;第 2.2 節
專業術語表只收外部通行的技術詞彙(OOF、CV、blend 等),不收自造詞。細節見文末 R-W10。

## 1. 競賽目的(what / why)
- What:競賽要解決的問題(一段)。來源:competition.description、competition.name
- Why:為何重要/評估指標為何合理(一段)。由 competition.evaluation_metric 與
  problem_type 反推(如 MAE → 對離群值穩健的絕對誤差)
- 基本資訊表:名稱、URL、問題型別、指標、優化方向。來源:competition.*(不含紀錄完整度
  ——那是 metadata 區塊的欄位,見 R-W1,不重複進表)

## 2. 本場工具、專業術語與採用策略

本節分三子節,**只放本場特有內容**;共同內容(工具鏈、專業術語表、階段定義)一律在《前言》,
報告不重複。節首固定一則 blockquote(逐字):

> 全案共同的研究設計、實驗流程、工具鏈、專業術語與五階段定義,見《前言》
> (docs/PREFACE.pdf);本節僅列本場特有的部分。

以下「來源」皆為報告撰寫時的內部取數指引,不代表輸出文字可引用這些路徑名稱(R-W11)。

### 2.1 本場工具
- 只寫本場**特有**者,以短句(非表格)呈現:樹搜尋工具本場用第幾版、特殊 CV 設計一句話
  (指向第 3.3 節)、本場獨有的後處理工具(如 OptimizedRounder、snap-to-grid,定義放
  2.2)。全用共同工具就寫一句:「全數為共同工具鏈(見《前言》第 3 節),無本場特有工具;
  樹搜尋工具本場使用第 N 版。」
- **不放**共同工具表(LGB/XGB/CAT、Optuna、uv、scikit-learn 等在《前言》第 3 節)、
  **不放**「LLM 決策 + Auto-ML 執行」分工原則段(在《前言》第 3 節)。
- 版本號等**未進入 facts.json 的數字**:一律放 fenced code block(verify_report.py 對
  code block 豁免),或乾脆不寫版本號。

### 2.2 本場專業術語
- 固定表格「專業術語 | 定義」:只列「本報告正文**實際用到**、且《前言》第 5 節
  **沒有**」的詞;《前言》第 5 節已有定義的詞(OOF、blend、solo、seed bagging、
  mega-blend、探索爆發、lineage 等)**不得重複列**。
- 跨節反覆出現的語意澄清(如「原始/取整」「時序/隨機兩種 CV 不可比」等)一律在此以
  **一行**定義;正文其餘各節只掛「(原始)」「(取整)」這類簡短標記,不再重複解釋
  (R-W2)。
- 若本場無特有專業術語:刪除表格,改寫一句「正文所用專業術語均已見《前言》第 5 節,無本場
  特有專業術語。」
- 來源:報告作者依本場正文用字彙整;此表本身不含數字,不受 Hard Rule 1 拘束。

### 2.3 採用策略
- 開頭固定一句(逐字):「各階段與子階段的定義見《前言》第 6 節(編號跨場同義);下表列
  本場使用情形。」
- 固定表格「階段 | 簡稱 | 本場是否使用」,**全部列出**《前言》第 6 節字典的全部列
  (階段 1–5 + 全部子階段 1.1–5.2),一列不漏;「簡稱」欄**逐字照抄**《前言》第 6 節的
  「簡稱」欄,定義以《前言》為唯一出處,報告內不重寫定義。
- 「本場是否使用」欄填法:`使用` / `使用(附註)` / `本場未使用(原因可附)` / `本場未執行`;
  判定只依該報告現有內容與該場既有紀錄,不確定就標「本場未使用(無獨立紀錄)」。
  階段 5 目前全案尚未執行,一律標「本場未執行(全案規劃中)」。
- **不放**舊代號對照行——舊代號(Phase/tier)對照已收在《前言》第 6 節;報告全文
  (含 2.3)禁止出現 Phase/tier 字樣(R-W8)。
- 正文與第 3.2/4/5 節表格的「階段」欄,填法二選一:
  (a) 若該筆實驗**精確對應**字典中某個子階段的定義,填該子階段編號(純數字,如
      `3.2`),不加「階段」字首;
  (b) 若該筆實驗是整個階段的綜合體現、或無法對應單一子階段(如 skill 六階段首跑本身、
      線性迭代中未歸類的診斷性探針),填粗體主階段編號(如 `**2**`)——表頭已寫「階段」,
      值不重複該詞;內文散文敘述仍寫「階段 2」。
  子階段判定必須有本場既有紀錄佐證(通常即第 5 節子階段分數表中已有的行),不得為湊
  階梯新造判斷;無法判定時一律退回 (b) 的階段名稱,不得勉強對應。

## 3. 實驗方法
五個子節(3.1–3.5)合起來對應計畫書(乙)的五大元件(spec 內部對照用;報告正文標題僅寫
「實驗方法」,不附此括號說明);子節本身無額外必填內容,五大元件的必填內容分列如下。

### 3.1 資料規格
- 列數/欄位數/型別概述。來源:eda.n_rows_train/n_rows_test/n_features/numeric_features/
  categorical_features(若 eda 存在);否則 competition.notes、experiments[].n_features
- 目標分佈:mean/median/skew、是否整數、log 轉換候選。來源:eda.target.*
- 資料品質:缺失、重複、離群(zeros)、高共線特徵對。來源:eda.missing_train/
  duplicate_rows_train/numeric_stats/high_collinearity_pairs
- 特別規則(外部資料、每日提交上限)。來源:competition.special_rules
- facts.eda 為 null(missing 含 "eda_summary")或 material_level == "baseline-only"
  → 註明「本場未執行 EDA,以下僅資料基本形狀」;有 facts.eda 者不得再宣稱未執行 EDA。
  正文行文一律用「EDA」「本次分析」等白話指稱,不逐字引用 `facts.eda` 欄位路徑(R-W11)。

### 3.2 模型規格
- 使用的模型清單與各自分數表。來源:best.base_models(name/score/time_s)
- Ensemble 權重與分數。來源:best.ensemble.weights、best.ensemble.score
- 選型理由(敘述;可參考該場的進度筆記脈絡)
- 注意:最佳解紀錄以 OOF score 最小/最大選出,不考慮 CV scheme 是否一致、也不代表已
  提交;若最佳解與排行榜所屬實驗不同,報告必須如 s3e16 範例明確區分兩者。正文不逐字
  引用 `facts.best` 這類欄位路徑,一律說「最佳解紀錄」「本場最佳」等白話(R-W11)。

### 3.3 訓練規格
- CV 方案表:scheme、n_splits、seed。來源:best.cv(seed 無紀錄則寫「無紀錄」)
- Objective 與關鍵超參(有紀錄才寫)。來源:best.base_models[].params
- 為何用此 CV(敘述;可引用 eda.validation_hint 與該場進度筆記的 CV 決策脈絡)

### 3.4 推論程序
- 後處理步驟。來源:best.postprocess(無則寫「無後處理紀錄」)
- Submission 檔名與格式。來源:best.submission、competition.id_column/target_column。
  `id_column`/`target_column` 為資料欄位名而非內部檔案路徑,可逐字引用;但重建/產生
  submission 的**腳本檔名**不進本節文字,一律移至第 7 節(R-W11),本節如需指向可寫
  「重建指令見第 7 節」。

### 3.5 評估指標
- 指標定義(一句)+ 分數總表:各 base model、ensemble、(若有)Public/Private LB。
  來源:best.*、leaderboard
- CV↔LB gap:僅當 leaderboard 存在;差值以內嵌算式呈現並置於 fenced code block 內(Hard Rule 1;verify_report.py 對 code block 豁免,衍生數字一律走此模式)

## 4. 實驗軌跡
- 逐實驗分數表:`exp | 時間 | 決策分數 | 階段 | 摘要`。來源:trajectory;「階段」
  欄填法同 2.3 節末段規則。
- **不得**在本節(或全報告任何節次)放置舊制的「實驗階段對照表」(代號 | 白話名稱 |
  對應層級)——階段語言已於 2.3 節一次定義完畢,此表已隨統一階段語言廢除。
- 轉折敘述:分數躍升或關鍵轉折發生在哪筆、當時改了什麼(可參考該筆實驗紀錄的文字備註、
  進度筆記),至多 3 條「轉折」bullet(各 ≤3 行),標題格式「**轉折 N(exp X→Y,一句話
  定位)**」。正文不逐字引用 `experiments[].notes` 這類欄位路徑(R-W11)。
- 無法解析的紀錄(對應 unparsed):**為空**時整段(含句子)刪除,不寫「無法解析之
  紀錄:無」這類空白確認句;**非空**時原文列出,開頭用白話帶出(如「無法解析的舊格式
  實驗紀錄(原文照列):」),不寫 `facts.unparsed` 欄位路徑本身(R-W11)。

## 5. 效能對照(逐階段)(NEW)
- 標題固定為「效能對照(逐階段)」——不使用「消融」「四層消融」等統計學專業術語(R-W10),
  正文以「逐階段對照」指稱這個機制。
- 固定表格「階段 | 配置 | 分數 | 相對改善」,固定四列(階段 1–階段 4),對照
  `docs/benchmark_facts.json` 該場之對應 row(該檔內部欄位名稱仍為 tier1–tier4,僅報告
  正文呈現改用「階段 N」,且不逐字引用 `docs/benchmark_facts.json` 這個檔名,可泛稱
  「跨場對照紀錄」,R-W11):
  - 階段 1:基線(Claude Code 直接執行,未引入 skill;即 generic batch 通用批次管線)
  - 階段 2:+ kaggle-agent skill 六階段流程(EDA→特徵工程→建模→評估)
  - 階段 3:+ self-improvement 線性迭代(經驗庫驅動的逐項改進)
  - 階段 4:+ 樹搜尋(結構化搜尋特徵/模型/超參組合空間)
  - 「相對改善」欄:每列相對於**前一階段**(非階段 1 累計)的改善百分比——階段1→2
    隔離 skill 流程的價值、階段2→3 隔離自我改進迭代的價值、階段3→4 隔離樹搜尋的價值。
    階段 1 列無前階段,寫「—(基線)」。
  - 分數欄:直接抄跨場對照紀錄中對應 tierN.value(與該場實驗紀錄的 experiment_id 對應,
    可交叉核對)。
  - 相對改善數字若非既有值(逐階增量比例通常需要現算)→ 算式放 fenced code block
    (Hard Rule 1),code block 內部代號比照樣板寫作「階段1→2」(數字緊接、無空格),
    不寫 tier。
  - 若某階段與前階段數值相同:相對改善如實寫「0%(...依協定停止)」,不得省略或美化。
- 表後固定一句目標三聲明(逐字):「本場由導入報告功能後之版本執行,分數自階段 2 起未
  低於前一階段——符合計畫書目標三(效能不退步)」。
- 特殊場次計分方式注記(僅相關場次需要;語言一律改為階段,事實內容不變):
  - s3e19:階段 1 與階段 2/3/4 的 CV 方案不同(KFold vs TimeSeriesSplit),不可比,需
    另行註記改用階段2→3/階段3→4 比較。
  - s3e16:階段 2–4 皆為取整計分;需一句話帶過(呼應第 3.5 節已作的
    raw/rounded 澄清,不重複解釋)。
  - s3e20:階段 1 為同 CV 方案下的代理基線,非嚴格通用批次對照。

### §5 子階段分數表(選填)
- 標題固定「**子階段分數表**(定義見第 2.3 節;僅列本場有既有紀錄者)」,欄位
  「子階段 | 分數 | 出處」——比 §3.2 更精簡,不重複列優化辦法的文字定義(定義已在 2.3
  節),出處只需 `exp#` 或「`exp#` 紀錄的文字備註引用」。
- 規則:僅當實驗紀錄天然含有對應中間紀錄時才呈現,引用既有分數,不得為湊階梯加跑實驗;
  無資料場次僅呈現階段主表,不放此表。子階段編號、分數皆須與 2.3 節字典及第 3–4 節表格
  一致,不得另創數值。

## 6. 總結(NEW,敘述性)
- 3–5 段(每段 ≤4 行),完整故事線:資料特性 → 關鍵決策 → 各階段增益來源 → 最終結果與
  可信度。
- 段落內容一律引用前面章節**已出現**的數字或質性描述,禁止出現前面章節未出現過的新數字。
- 末段加「重現本實驗的最短路徑」小段(≤3 行),指向第 7 節,不重複列出指令本身。

## 7. 重現指令
- 從資料下載到 submission 的完整命令序列(bash code block)
- 來源:該場進度筆記的 Reproduce 節(有則沿用)或依 competitions/<name>/scripts/ 實際
  檔名組出
- 註明執行目錄與 uv 需求
- 各步驟註解可用 `(exp N)`/`(3.2)` 等階段語言標示對應實驗,不使用舊 Phase 代號
- **本節是全報告唯一允許出現腳本/檔案路徑(scripts/*.py、tree_search/*.py、
  experiments_tree.json 等)的地方**(R-W11);第 1–6 節提及對應動作一律改用白話動詞
  片語描述,不貼路徑。

## 寫作與排版規範(強制)

以下規則對所有報告一律適用,違反者視為未通過 rubric(見 rubric.md R9)。

- **R-W1 精簡的來源聲明,不進正文細節**:報告開頭 metadata 區固定兩行——第一行泛稱
  「本報告由自動化報告流程產生:所有數字直接取自實驗原始紀錄並經自動一致性驗證,敘述由
  AI 彙整。」,第二行「紀錄完整度:<完整|僅基線> | 產生日期:<日期>」;不得在此提及
  「kaggle-report skill」「facts.json」「verify_report.py」等內部工具/檔案名稱
  (R-W11)。正文其餘各節禁止逐項標「(來源:…)」。
- **R-W2 語意澄清只講一次**:如 raw/rounded 這類跨節概念,一律在第 2.2 節專業術語表以一行
  定義講清楚,其後全文一律用「(原始)」「(取整)」二字標記,不再重複解釋。
- **R-W3 無版本沿革**:報告永遠只呈現當前狀態;不寫「本次更新」「先前版本」——版本歷史交給
  git 管理。
- **R-W4 段落上限 4 行**:超過即改條列;每節先表格後敘述,敘述只寫表格讀不出來的 why。
- **R-W5 實驗一律稱 exp N**:表格中最佳值以粗體標示。
- **R-W6 固定表格 schema**(逐節列出,欄名一字不差):
  - §1 基本資訊表:`項目 | 值`(競賽/問題型別/評估指標(方向)/目標欄位;不含紀錄完整度)
  - §2.1 本場工具:短句敘述,無固定表格(全共同工具時一句帶過)

## PDF 管線(md2pdf.sh)

- `assets/md2pdf.sh <REPORT.md> [out.pdf]` 將報告轉為 PDF,並**自動**注入:
  - 目錄(收 h2 + h3 兩層,插在第一個 h2 之前;h2 少於 3 個的短文件不加目錄);
  - 每頁頁尾頁碼與目錄各節頁碼(CSS 分頁計數)。
  報告 markdown 本身**不需**手寫目錄或頁碼。
- 引擎:weasyprint 為主引擎(唯一支援目錄頁碼與頁尾頁碼);失敗時自動改用 chromium
  備援——備援仍產出 PDF 與目錄清單,但沒有頁碼。
- 離開碼契約不變:`0` = PDF 已寫出;`2` = 兩引擎皆不可用(此時 .md 為交付物,須告知
  使用者);`3` = 引擎回報成功但檔案不存在(視為失敗回報)。
- PDF 檔名沿用 `<short>_REPORT.pdf` 慣例(如 `s3e16_REPORT.pdf`);產出後以
  `pdftotext -f 1 -l 1 <pdf> - | grep 目錄` 確認目錄有印出。
