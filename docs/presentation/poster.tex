% ---- 1 · Motivation --------------------------------------------------------
\begin{secblock}
\blocktitle{1\sep Motivation}
\cardsub{Challenges of Kaggle competitions}
\begin{itemize}
  \item The full expert loop: validation design, feature engineering, model
    selection, ensembling. Top entries are separated by a \kb{very small
    margin}.
  \item \kb{Data preparation} is essential but repetitive: every dataset needs
    the same cleaning, split design and drift checks before any model can be
    trusted.
\end{itemize}
\cardsub{Why an AI agent}
\begin{itemize}
  \item A competition is a \kb{scorable task}: every candidate returns a
    number, so it can be \kb{optimized automatically}
    (propose, score, keep the better, repeat).
  \item Tireless, systematic search over candidate configurations, every
    experiment logged and reproducible.
  \item Records a per-dataset EDA pass and writes a per-competition report
    automatically, so every claim is grounded in an artifact.
\end{itemize}

% ---- 4 · Reflections ------------------------------------------------------
\begin{secblock}
\blocktitle{4\sep Reflections}
\begin{itemize}
  \item \kb{Put knowledge injection upstream.} At the blend stage it measured
    near-nothing and was abandoned; moved into problem identification it
    \kb{improves scores significantly}.
  \item \kb{No score until you submit.} A competition cannot be graded on
    the spot. While you iterate, local CV is all you see, so an error in
    problem-level judgment leaves CV looking healthy while the leaderboard says
    otherwise.
  \item \kb{Freeze the architecture before you measure.} One results table can
    report only one agent version, so an architectural change invalidates every
    run before it. That is why such a change costs twice: a tail of bugs to fix,
    then a full re-run to earn the voided scores back.
  \item \kb{Get isolation right.} If a lane can reach a leaderboard or another
    lane's work, every number in the table is worthless. It has to be enforced
    by the setup, not by telling the agent what to avoid.
\end{itemize}
\end{secblock}

% ---- 5 · Where AI-heavy work falls short -----------------------------------
\begin{secblock}
\blocktitle{5\sep Weaknesses of AI-heavy research}
\begin{itemize}
  \item \kb{Strong hands, no design judgment.} Implementation is fast and
    accurate, but the loop only solves the problem it is handed. It never asks
    whether a change is worth making, and nothing in it can tell whether an
    architecture holds until the runs come back, by which time the debt is
    already there.
  \item \kb{The question gets lost in the detail.} Heavy AI use pulls a
    write-up toward the technical detail it can report exhaustively, and away
    from the one thing the reader came for.
  \item \kb{AI writing habits survive review.} Redundant heading suffixes and
    invented terminology come back in every draft; keeping them out is manual
    work, not a setting.
\end{itemize}
\end{secblock}
