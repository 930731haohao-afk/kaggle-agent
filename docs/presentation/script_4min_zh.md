## 0 · 標題（18 秒）

各位老師好，我是政大黃威昊，指導老師是中研院顏佐榕老師。Sinica 是端對端的 Kaggle agent，原始資料進去，提交檔出來，中間沒有人。我讓它跟兩個固定版本的 agent，在二十三場競賽比成績。

## 1 · Motivation（32 秒；末句前人工作約 7 秒，時間緊可略）

Kaggle 競賽要的是一整套專家流程，從驗證設計一路到 ensemble，分數又擠得很近，三個 agent 之間好幾場差在小數點後第四位。而每份資料都還得先做一遍差不多的清理和切分。競賽的好處是每個做法都會給出一個分數，可以自動找最好的那一組。agent 不會累，每一步都留紀錄，一場競賽可以評估三十七到兩百二十四個節點。這條路線近期已經有人在跑，AIDE 是在程式碼空間做樹搜尋，Nature 那篇再餵進注入的研究想法。

## 2 · Workflow（40 秒；末句規格報告約 8 秒，時間緊可略）

這張圖從上往下讀。每個階段都由 LLM 決策，模型配適交給 gradient boosting，外面包一層樹搜尋，把整套解法當成一個節點來比較。關鍵的決定是外部知識從哪裡進來。第一版放在下游的模型融合，量出來對分數的影響只有十的負五次方，等於沒有；所以往上游搬，先判定問題性質再建模。另外，每次執行都關在獨立環境裡，不放 Kaggle 憑證，全程碰不到排行榜。每場跑完，agent 還會從執行紀錄自動產出一份五節的 ML 規格報告，這是另外兩個 agent 沒有的功能。

## 3 · Results（45 秒）

二十三場都算成績：二十場提交到真實的 private 榜，三場特殊競賽用 MLE-bench 離線計分。整體來看，二十三場裡我們拿到十三勝十敗，是三個 agent 中最好的。更嚴格的看法是把公私榜的分數雜訊當尺：六十組兩兩比較裡三十八組分得出勝負，Sinica 在自己判得出的組裡十六勝八敗，百分之六十六點七，兩個對手各只有四十二點三。輸最慘的兩場都已經有成熟的公開解，那裡複現贏過自主搜尋。

## 4 · Disadvantages of the agent-based approach（45 秒）

先講這個做法的缺點。它寫程式很有效率，交給它的問題都能做下去，但它不會問這個改動值不值得做，常常因此選錯設計、留下一堆 bug。第二，它只能對著本地驗證分數優化，所以 CV 可能很漂亮，真榜卻普通。第三，大量用 AI 寫，內容會一直往技術細節堆，離讀者真正想知道的事愈來愈遠。第四，AI 的寫作習慣——冗餘的標題、自創的術語——每一稿都會回來，只能靠人逐條驗證修改，非常費工。

## 5 · Practical advice for building AI agents for data science（38 秒）

如果要自己做，三個建議。第一，先把隔離做在環境裡，agent 跑起來就碰不到排行榜、也碰不到別條 lane 的檔案。第二，動手建 pipeline 之前先把設計想清楚、說得出理由；中途改設計，除了修 bug，之前跑過的競賽還得花成本重跑。第三，外部知識要在建模之前注入；放在最後一步幾乎沒有效果，搬到前面分數就明顯變好。

## 6 · References（過場，時間不夠可跳過）
