% ============================================================= 1 MOTIVATION --
\begin{frame}{1 Motivation}
  \vspace{0pt}
  {\small\bul\kb{Challenges of Kaggle competitions}\par}
  \vspace{2mm}
  {\small
   \sitem{A competition requires the expert loop}{This includes validation
     design, feature extraction, model selection, and ensemble building. The
     top entries are separated by a very small margin.}
   \sitem{Data preparation is repetitive}{The same cleaning, split design, and
     drift checks are done on every dataset.}}
  \vspace{2.5mm}
  {\small\bul\kb{Why an AI agent}\par}
  \vspace{2mm}
  {\small
   \sitem{A competition is a \emph{scorable} task}{Every competitor delivers
     a number, so it can be optimized automatically.}
   \sitem{A competition requires tireless, systematic search}{Every experiment
     is recorded and should be reproducible.}
   \sitem{Recent success of agents for Kaggle competitions}{Notable cases
     include tree search over code~\cite{aide2025}, and tree search fed
     injected research ideas~\cite{aygun2026}.}}

  \note{Competitions demand the whole expert loop, and the top of the
    leaderboard separates at the fourth or fifth decimal, so tuning skill
    distinguishes nobody. Before any of that, every dataset needs the same
    repetitive preparation. What an agent brings is tireless, logged search:
    between thirty-seven and two hundred and twenty-four candidate
    configurations per competition, and the same protocol run twenty times
    without drifting. (32s)}
\end{frame}

% ============================================================== 2 WORKFLOW ---
\begin{frame}{2 Workflow}
  \vspace{0pt}
  {\small\kb{From raw data to a scored submission}\par}
  \vspace{1.5mm}
  \centerline{\includegraphics[height=0.66\textheight]{fig1_arch_slide.pdf}}
  \vspace{1.5mm}
  {\scriptsize\color{mut}The LLM reasons and decides at every stage; the
   problem dossier classifies the task and injects external data
   \emph{upstream}, before any modeling. EDA then tests the dossier's
   hypotheses, feature engineering and modeling follow, and evaluation returns
   the score the tree search uses to pick the next candidate. Each run also
   automatically writes a per-competition report.\par}

  \note{The pipeline reads top to bottom. An LLM reasons and decides at every
    stage, gradient boosting does the fitting, and a tree search over complete
    candidate solutions is the optimization loop. The one design decision that
    mattered is where outside knowledge enters. My first version put it
    downstream, at the blend --- measured, it was worth ten to the minus five.
    So it moved upstream, into a dossier stage that classifies the task before
    any modeling. The lanes hold no Kaggle credentials, so nothing inside a run
    can touch a leaderboard. If time allows: each run also writes a
    five-section ML specification report from its logged records --- neither
    reference agent does this. (40s, +8s with the spec-report sentence)}
\end{frame}

% ==================== 4 DISADVANTAGES OF THE AGENT-BASED APPROACH ---
\begin{frame}{4 Disadvantages of the agent-based approach}
  \vspace{0pt}
  {\small
   \ritem{The agent is strong at coding, weak at judging}{The agent
     efficiently works through whatever problem it is given. However, it does
     not ask whether a change is worth making. This often leads to a poor
     design choice that yields bugs.}
   \ritem{The agent can only target the local validation score}{As a result,
     the local validation score can look outstanding while the real
     leaderboard score is mediocre.}
   \ritem{The agent often buries the main question in detail}{AI-written
     reports put too much focus on technical details, drifting away from what
     the reader wants to know.}
   \ritem{The agent has bad writing habits}{Redundant headings and reinvented
     terms often come back in every draft. Verifying and modifying them by
     hand is exhausting.}}

  \note{Where the approach falls short. The agent codes efficiently, but it
    has no design judgment: it never asks whether a change is worth making,
    so a poor design choice slips in and yields bugs. Its iteration can only
    target the local validation score, which can look outstanding while the
    real leaderboard score is mediocre. Heavy AI use also pulls a write-up
    toward technical detail and away from the question the reader came for.
    And its writing habits --- redundant headings, reinvented terms --- come
    back in every draft; verifying and fixing them by hand is exhausting.
    (45s)}
\end{frame}

% ================= 5 PRACTICAL ADVICE FOR BUILDING AI AGENTS ---
\begin{frame}{5 Practical advice for building AI agents for data science}
  \vspace{0pt}
  {\small
   \ritem{Build an isolated environment before running the agent}{This
     prevents any access to the leaderboard or another run's files.}
   \ritem{Justify the design before building the pipeline}{This mitigates
     redesign cost, debugging time, and a full rerun of earlier
     competitions.}
   \ritem{Inject external knowledge before data modeling}{This often improves
     the score. However, if those external data are injected at the final
     step, the score shows almost no improvement.}}

  \note{Three pieces of advice for anyone building one of these. Build an
    isolated environment before running the agent, so a run simply cannot
    reach the leaderboard or another run's files. Justify the design before
    building the pipeline --- a redesign costs debugging plus a full rerun
    of earlier competitions. And inject external knowledge before data
    modeling --- at the final blending step it bought almost nothing; before
    modeling it clearly helped. (38s)}
\end{frame}
