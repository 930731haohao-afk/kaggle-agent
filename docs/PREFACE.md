# 前言:全案共同方法、工具與專業術語

本文件是整個競賽實驗系列的共同總覽:研究設計、實驗流程、工具鏈、專業術語與階段定義
集中在此,各場競賽報告不再重複。本文件為方法說明,不含任何實驗數字;各場數據見
各場競賽報告,跨場彙總見總結報告(SUMMARY_REPORT)。

> **閱讀方式**:先讀本前言,再讀任一場競賽報告,最後讀總結報告。各場報告的第 2 節
> 只列「本場特有」的工具與專業術語,以及本場各階段的採用情形;在報告正文遇到不認識的
> 詞,先查該報告第 2.2 節,再查本前言第 5 節專業術語表。

---

## 1. 研究目的

本專案評估 AI agent(Claude Code)自主參加 Kaggle 表格資料競賽的能力。
做法很直接:**同一場競賽解五次,一次比一次多給一項方法**——從沒有任何輔助的
基線開始,依序加入競賽流程 skill、線性自我迭代、樹搜尋(取代線性迭代)、
外部想法注入——再比較五次的分數,就能看出每一項方法各帶來多少改善。
每場報告的第 5 節「效能對照」列出該場五次的分數;總結報告彙整跨場結論。

五個配置即「階段 1–5」,完整定義見本前言第 6 節。

## 2. 共同實驗流程

每場競賽都走同一條流程:

1. **資料理解(EDA)**:欄位型態、目標分布、缺失與異常、洩漏風險。
2. **CV 設計**:依資料性質選擇切分方式(分層/分箱/時序),此後全場固定同一組折,
   確保跨實驗分數可比。本系列各場皆採 5 折。
3. **特徵工程**:由 EDA 發現引導的衍生特徵。
4. **建模與集成**:多個模型各自完成 K 折訓練(solo),再以 OOF 權重搜尋合成 blend。
5. **評估與決策**:一律以 OOF 分數決策,不看單折、不看訓練分數;可提交的場次
   再以排行榜複核本地驗證是否可信。
6. **提交(開放場次)**:先通過 OOF 重現閘門,才產生 test 預測並提交;
   競賽已關閉提交者標記 CV-only。

**紀錄與報告**:所有實驗寫入統一格式的原始紀錄;報告中的數字由程式直接從原始紀錄
抽取,並經自動一致性驗證,敘述由 AI 彙整。

## 3. 共同工具鏈

| 工具 | 用途 |
|------|------|
| Claude Code(LLM agent) | 全流程決策:模型選型、特徵工程、停損判斷、報告敘述 |
| kaggle-agent skill | 競賽流程操作手冊:EDA→CV 設計→特徵→建模→評估→提交 六階段 |
| self-improvement skill | 線性自我迭代與跨競賽經驗庫的操作手冊 |
| kaggle-report skill | 報告自動產生:事實抽取、數字一致性驗證、PDF 輸出 |
| LightGBM / XGBoost / CatBoost | 三個梯度提升樹模型,所有集成的基礎成員 |
| scikit-learn | 交叉驗證切分與評估指標計算 |
| Optuna | 超參數自動搜尋(階段 3 起使用) |
| 自建樹搜尋工具 | 階段 4 的候選樹搜尋:第 1 版節點為單一模型、第 2 版節點為 blend、第 3 版加入預算相位機與自動停止 |
| uv | Python 套件與環境管理,所有腳本以 `uv run` 執行 |

分工原則:LLM 負責判斷與決策(選什麼方向、何時停),AutoML 工具(Optuna、樹搜尋)
負責系統化的搜尋執行,兩者互補。

## 4. 評估與分數的通用約定

- 每場競賽用該場官方指定的評估指標(MAE、RMSE、ROC-AUC 等),於各場報告
  第 3 節說明;指標的優化方向(越小越好或越大越好)以該場報告為準。
- 本地分數一律指 OOF 分數;排行榜分數一律標明 Public 或 Private。
- 同場所有實驗共用同一組折,分數才可直接比較;跨場分數不互比(指標與資料不同)。

## 5. 全案專業術語表

正文常用詞,依主題分組。

**實驗與驗證**

| 專業術語 | 定義 |
|------|-----------|
| exp N | 該場報告中第 N 筆實驗紀錄的編號(場內編號,跨場不互通) |
| CV / 折(fold) | 交叉驗證:訓練資料切成 K 份輪流當驗證集,以平均分數評估模型 |
| StratifiedKFold(分層 K 折) | 各折保持指定類別(或分箱)比例一致的切分方式 |
| OOF | out-of-fold:每筆訓練樣本由「未見過它的那折模型」預測,拼回全訓練集後計算的分數;全案所有本地決策的依據 |
| CV↔LB gap | 本地 OOF 分數與排行榜分數的差距,用於檢查本地驗證是否可信 |
| CV-only | 該結果僅有交叉驗證分數、沒有排行榜分數可對照(競賽已關閉提交等原因) |
| Public / Private LB | Kaggle 排行榜:Public 為賽中可見的部分測試集分數,Private 為決定最終名次的另一部分 |
| OOF 重現閘門 | 提交前把最佳解的全部成員從頭重訓,逐位比對 OOF 與搜尋當時的快取一致,才允許產生 test 預測 |
| 巢狀驗證 | 把「選擇」這個動作(選特徵、調權重)也放進驗證:在部分折上做選擇,用沒參與選擇的折驗分數,避免選擇本身造成過度樂觀 |

**建模與集成**

| 專業術語 | 定義 |
|------|-----------|
| solo | 單一模型(單一組超參數)的完整 K 折訓練結果 |
| blend / 權重搜尋 | 多個 solo 的 OOF 加權平均;權重由演算法在 OOF 上搜尋而得 |
| seed bagging | 同一組超參數換隨機種子重訓,加入集成以降低隨機波動 |
| 目標編碼(TE)/ fold-safe | 以群組的目標平均值作特徵;fold-safe 指編碼所用的折與模型訓練折完全一致,杜絕跨折洩漏 |
| rank-average | 各模型的預測值先轉成名次(排名)再加權平均;對輸出大小尺度不同的模型更穩 |
| 經驗庫 | 跨競賽累積的「什麼有效/什麼無效」條目,供後續場次作先驗 |

**樹搜尋(階段 4)**

| 專業術語 | 定義 |
|------|-----------|
| 節點 | 樹搜尋中的一個候選配置(一個 solo 或一個 blend) |
| lineage(系譜) | 由根節點某直接子節點衍生的整條後代鏈,代表一個優化方向 |
| plateau | 某 lineage 連續數次未刷新全域最佳而被凍結,搜尋轉往其他方向 |
| explore burst(探索爆發) | 全部 lineage 皆凍結後,強制注入的一批新起點 |
| mega-blend | 把當時全部 solo 成員都納入的大集成 |
| 邊界推進 | 調參搜尋範圍的邊緣值再往外推一步的嘗試(如把學習率壓到搜尋下限之外) |


## 6. 階段與子階段定義(全案字典)

實驗依「使用的方法架構」分為五個階段,階段內的具體優化辦法以子階段(如 1.1)表示。
編號與簡稱在所有競賽報告中意義相同,可跨場直接對照;各場報告第 2.3 節只列
「編號、簡稱、本場是否使用」,定義以本表為唯一出處。

| 編號 | 簡稱 | 定義 |
|------|------|------|
| **1** | 無 skill 基線 | 未使用 kaggle-agent skill:Claude Code 直接執行通用 AutoML 腳本 |
| 1.1 | 單模型基線 | 單一模型、預設參數、原始特徵 |
| 1.2 | 三模型 blend | 三個梯度提升樹模型 + OOF 權重搜尋 blend |
| **2** | kaggle-agent skill | 依 skill 的六階段流程作業:EDA→CV 設計→特徵工程→建模→後處理→提交 |
| 2.1 | EDA 驅動 CV 設計 | 依資料性質設計切分(分層/分箱/時序) |
| 2.2 | EDA 驅動特徵工程 | 由 EDA 發現引導的衍生特徵 |
| 2.3 | 指標感知後處理 | 依評估指標調整目標與輸出(取整、objective 對齊等) |
| 2.4 | 場內反思回退 | 單輪反思(reflexion):嘗試失敗即回退上一版 |
| **3** | +線性自我迭代 | 階段 2 加上「一次改一件事、固定停止準則」的逐輪優化 |
| 3.1 | 經驗庫先驗 | 以跨競賽經驗庫引導迭代方向 |
| 3.2 | Optuna 超參搜尋 | 自動調參,調參後模型納入集成池 |
| 3.3 | 調參入池 | 調參模型「加入」集成池而非取代原成員 |
| 3.4 | seed bagging | 調參模型換隨機種子重訓再入池 |
| 3.5 | 結構化去噪 | EB 收縮/異常期降權/鄰域平滑等訊號去噪 |
| **4** | +樹搜尋 | 階段 2 加上候選樹+回溯機制的組合空間搜尋(取代線性迭代) |
| 4.1 | 單模型節點樹 | 節點=單一模型配置(工具第 1 版) |
| 4.2 | ensemble 節點樹 | 節點=blend 配置,直接以最終計分方式的分數評分(如取整後計分)(工具第 2 版) |
| 4.3 | 先驗注入+去重 | 經驗庫先驗引導擴展方向,子節點去重 |
| 4.4 | 邊界推進 mutation | 以邊界推進產生新節點的擴展方式 |
| 4.5 | 預算相位機 | 把運算預算分成幾個時期(先廣後深)排程,加上探索爆發與自動停止(工具第 3 版) |
| **5** | +外部想法注入 | 階段 4 加上外部文獻想法庫(全案規劃中) |
| 5.1 | 外部想法庫先驗 | 文獻與冠軍方案的想法注入搜尋先驗 |
| 5.2 | 重組 mutation | 取兩個高分節點的核心概念合成新解 |

> 對照原始紀錄用:歷史紀錄文字中的舊代號 Phase B 即階段 3、Phase E-3 即階段 4、
> tier1–4 即階段 1–4;所有報告正文一律不使用舊代號。

## 7. 各場報告的結構

每份競賽報告固定 7 節:

| 節 | 內容 |
|----|------|
| 1 競賽目的 | 這場比什麼、評估指標與資料概要 |
| 2 本場工具、專業術語與採用策略 | 僅本場特有的工具與專業術語;2.3 為本場各階段採用情形表 |
| 3 實驗方法 | 資料規格與實驗總表(所有數字的出處) |
| 4 實驗軌跡 | 按時間順序的決策敘事:為何這樣做、結果如何 |
| 5 效能對照 | 逐階段分數對照:每一階段比前一階段改善多少 |
| 6 總結 | 本場學到什麼、哪些作法有效 |
| 7 重現指令 | 從原始資料重現最佳解的完整指令 |

報告 2.3 節「本場是否使用」欄的意義:**使用** = 該階段/子階段在本場有實際執行;
**本場未使用** = 全案字典中有此項但本場未執行(或無獨立紀錄);規劃中的階段
標「本場未執行」。
